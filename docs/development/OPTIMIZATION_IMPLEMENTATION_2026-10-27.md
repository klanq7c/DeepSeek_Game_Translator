# 首批优化实施与边界

日期：2026-10-27。当前版本输入为 0.4.1.1；本次是工作区实施，不包含版本升级或发布。
前置候选及原始分析见 [优化审查](OPTIMIZATION_REVIEW_2026-10-25.md)。

## 改动范围

1. **Unity 只读审计**：复用 Mono 原有标签表和完整标签边界，比较有序标签及属性，正文占位符允许调序。逐对消费字面花括号，识别 `{{{0}}}` 内的真实格式字段；noparse 内的引号、尖括号不吞掉结束标签。审计不改写共享缓存或游戏资源。
2. **RPG Maker 空扫描**：仅在至少一张位图有可用 OCR 区域时发现可见目标；使用数量避免强引用保留位图。未调用 destroy 就被回收的对象可能留下保守非零计数，只损失优化收益。候选存在时仍逐帧发现，保留同场景增加/显示 Sprite 与替换 bitmap 的能力。迟到 OCR 不能复活已销毁对象或已关闭模块。
3. **C# 实时批量**：所有实时入口在同一锁内按整组准入 32 MiB 预算，由专用 worker 按已有数量/UTF-8 预算分块，保持并发、去重回填顺序、`api_batch` 和失败拆分。逻辑记账仍是 UTF-16 文本与每项 64 字节，不等于精确堆峰值；释放预算先于持久化的既有时机保留。C 侧原来已有预算工作池。
4. **启动器服务操作**：C/C# 共用各自唯一的 UI 操作执行器，覆盖开始翻译、还原、清缓存和手动启停。预留覆盖确认弹窗、工作线程与完成弹窗。路径使用私有快照；线程句柄由 UI 持有到真实退出，心跳执行最终弹窗。关窗等待在途操作完成并抑制最终弹窗。创建线程失败记录错误、释放预留，不回退到 UI 阻塞执行。停服失败不删除缓存，删除后重启失败仍报告。命令行诊断模式继续同步。

## 回归证据

- 入口守卫在修复前确认两版清缓存/启停调用服务边界的线程就是 UI 线程。
- Unity 新增组合花括号用例在修复前漏掉两个精确疑点键；另一个失败守卫保护共享标签语法允许的空白结束标签，防止 noparse 吞掉缺失结束标签的差异。最终四引擎审计通过，Unity 十八对输入的八个疑点键精确匹配。
- 启动器源链接真实四入口与执行器，用事件持有后台边界；验证非阻塞、所有入口互斥、确认弹窗重入、取消和线程创建失败后的释放、停服/重启失败、开始与还原路径快照，以及关闭时的回调所有权。
- 真实双服务批量夹具检查非零预算、多通道、去重顺序、耗尽拒绝、连接断开后预算释放、排队/在途组关停；全部使用自有动态端口与临时缓存。
