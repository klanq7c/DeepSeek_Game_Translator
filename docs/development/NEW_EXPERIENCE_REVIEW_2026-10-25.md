# 新增汉化经验核查（2026-10-25）

依据用户新版多游戏经验整理，与现有 0.4.1.1 工作区逐项核对。
后续百分比说明误报及未闭合片段漏报的修复见 [审计边界复查](AUDIT_REVIEW_2026-10-25.md)。
本轮实际代码改动仅在只读审计工具的 Ren'Py 分支，不改变游戏运行钩子、
服务器、缓存格式、字体或原游戏文件；另补 Godot 包内缓存的对照守卫。

## 采纳结果

| 新经验 | 核查与处理 |
| --- | --- |
| `{}` / `{0:.2f}` 是格式模板，不能都当成非法文本标签 | 审计只对比完整结构，不调用游戏标签验证器断言模板非法；保留完整模板不报疑点，丢失或改写字段会报告。 |
| 标签、插值、旧式变量必须完整，不能只看计数 | Ren'Py 审计改为专用词法扫描，保护 `[player]`、嵌套下标、空/数字格式字段、长标签、旧式映射字段和标记顺序。 |
| 误报要与原文对照 | `[[` / `{{` 中的可见字面量允许翻译；源文与译文同有未闭合片段时比较结构种类，不用已翻正文制造差异。此项不代表原文语法正确。 |
| 导出缓存里也可能有 UI 文本 | PCK 中的 `.scn` / `.res` 已在第二轮采集，添加 `.godot/exported/` 路径的原包不变及扫描优先级守卫。松散编辑器缓存可能过期，继续跳过。 |
| 哈希的有符号表示要归一化 | 当前 OptimizedTranslation 路径以 `uint32_t` / `uint` 读取原记录并保留哈希字节，不以有符号十进制字符串重新匹配键；本轮没有新增哈希转换或承诺新格式支持。 |
| FontGroup 的首段优先、默认段及 emoji 回退 | 本地 Ren'Py 7.8.7 / 8.1.1 的原生实现确认先添加优先。通用接管还要同时保留字符重映射及全局字体替换语义，不能只改 `.add()` 顺序；本轮未改动运行时字体接管。 |
| mod 的 label 覆盖、广告套件移除、强制语言 | 属于游戏故事逻辑及第三方组件策略，没有自动改 mod、删除游戏文件、去广告或改写存档。 |
| 大批量 TM 精确复用 | 继续现有以原文为键的缓存和持久化机制，不按行号迁移，不因游戏系列相似而重写已有译文。 |

新版资料仍含不能直接推广的结论：松散脚本与归档并存不等于一定重复执行，
官方 `replace_text` 默认接收插值及标签拆分后的正文；未包 `_()` 也不能单凭
静态源码判定显示阶段绝不会走翻译表。沿用前轮针对实际引擎的核对结果，
不据此自动重写游戏源码或覆盖原始编译脚本。

## 审计改进

旧通用正则漏掉 Ren'Py 方括号插值、空和数字格式字段，并有 80 字符边界；
排序比较也无法发现标记顺序变化。新增实际源文件→启动器扫描→持久缓存→审计
夹具先复现失败，修复后扩展至十二条源文：报告七个预设结构疑点，其余五条不误报。

新解析器只用于 Ren'Py；其他引擎的控制码、计时分类和已有 JSON 字段不变。
旧式 `%()` 键支持空键与平衡括号，后缀使用固定起点及原子组匹配，避免损坏长串
导致反复回溯。没有自动修复或写回缓存；重排变量可能是有意的，报告仍是人工
复核线索，不等于一定崩溃，也不评价实际渲染和语义。
