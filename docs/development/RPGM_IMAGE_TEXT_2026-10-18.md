# RPG Maker 通用图片文字翻译（2026-10-18）

后续状态提交和 OCR 协议复查见 [图片翻译复查](RPGM_IMAGE_REVIEW_2026-10-18.md)。

影响范围：RPG Maker MV/MZ 渲染适配、启动器部署及内嵌资源。共享服务器协议、翻译记忆格式和其他引擎的文字处理不变。

## 原因与自动流程

部分菜单插件把标签绘制在图片内，并禁用普通窗口文字。恢复这些方法会叠字、改变布局；普通文字入口也无法接收到图片中的标签。

用户要求通用补丁，因此默认流程自动发现图片、识别文字、取得译文并绘制到独立 Bitmap，无需游戏专用清单、词表、坐标或提前制作译图。当前游戏只作为回归样本。

1. `ImageManager.loadBitmap` 保留引擎的加载、解密、色相及参数处理。候选目录为菜单、UI、HUD、系统、图片和标题，排除角色、地图块、图标集、仪表与粒子等资源。
2. 原图完成加载后立即提供同尺寸副本，识别异步执行。原始文件和引擎缓存位图不被翻译器修改。
3. `dst_rpgm_ocr.ps1` 使用系统 Windows 英文 OCR；透明图片分别衬黑、衬白并放大识别，返回原图坐标。工作进程只通过标准输入接收已解码 PNG，不读游戏文件，不联网。
4. 标签由当前游戏的系统术语和装备类别校正；未知词须通过两个背景的文字与位置一致性校验，矛盾的有效术语不覆盖。没有特定游戏的标签表。
5. 只有两侧能验证为连续背景的区域才替换；复杂背景、越界和放不下译文的区域保留原图。字体就绪后在暂存画布恢复局部背景、缩字绘制，完成后一次提交。
6. 原文进入已有非阻塞缓存和翻译入口；未命中、排队响应保留原图。成功显示的译文保留在该位图中，查询缓存淘汰或迟到未命中不会使其消失。
7. 场景更新有界发现可见纹理，覆盖同场景新添或重新显示的 Sprite。目标、字体和缓存代次不变时不查询译文、不重画；离场目标引用随下一次更新释放。

工作进程最多排队 16 项，一次处理一张图片；单 PNG 不超过 2 MiB，像素不超过 2,097,152；启动等待 8 秒、单请求 15 秒、空闲 10 秒后退出。原始识别结果按内容摘要复用，最多保留 64 张图。两版启动器自动部署、更新、还原两个辅助文件，资源字节一致。

旧的可选指纹清单入口保留兼容，但自动流程不依赖它。回归样本停用此前手工清单，旧译图不参与自动验证及默认部署。

## 支持边界与故障

- 自动图片识别当前用于 Windows NW.js 的 RPG Maker MV/MZ，需要系统英文 OCR 语言包。这不是其他引擎的图片 OCR，也不保证识别所有艺术字体或复杂背景。
- 插件须经过引擎的 `ImageManager.loadBitmap`。绕过入口、动态修改同一原始位图或直接使用 GPU 纹理的路径不在本次支持范围。
- OCR 仍可能误判；无法可靠处理的区域保留英文。译文质量由既有缓存和提供方决定。
- Windows PowerShell 5 默认代码页可能误读无 BOM 中文注释，父进程显式按 UTF-8 加载脚本；路径按字面字符串传入，不经过 shell 插值。
- 系统语言、进程、解码、字体、背景、绘制和容量故障分别记录 `image-ocr-*` / `image-text-*`，经既有诊断器限频，不写成功翻译或共享缓存。

## 验证

- 自动渲染回归覆盖无清单、数据驱动术语、未知词双背景一致、歧义拒绝、异步加载、字体就绪、背景与原图保护、缓存淘汰、位图销毁、平滑参数、同场景可见性变化、部分绘制失败和进程归属。
- 真实 Windows OCR 识别另一张不同尺寸、位置和文字的合成纹理，同一进程处理坏 PNG 后仍能识别后续请求，故障带请求号。
- 源链接实际样本 Bitmap/ImageManager，使用真实系统 OCR 和独立原生画布，不读取手工清单或译图：4 张菜单纹理自动识别并显示 16 个标签，3 张无字纹理没有生成区域；独立布局合成图识别并显示 2 个标签。
- 5 张有字纹理各重画 60 帧，清空夹具查询结果后像素仍稳定，原始位图摘要一致。样本译文来自本地服务，合成图使用独立测试译文。
- 回放替代浏览器图像 I/O 和 GPU 上传边界，不等同于完整游戏实机游玩。原始日志与本机资源仅保存在 `.scratch/`，不进入公开下载包。
