# 0.4.1.1 源码发布内容扫描修复（2026-11-06）

## 问题与范围

Unity 引用缓存收尾时，源码准备与独立发布审计均退出 1：凭据模式命中了 C UI 探针的
密码掩码布尔标志，以及 PowerShell 一致性测试中的对应断言。这两处输出的是状态，
不是用户密码。真实源码行组成的隔离夹具复现了相同失败。

本项只修改源码发布检查、测试及开发文档。运行时、C/C# 启动器探针协议、版本号、
用户配置、游戏文件和已构建程序均保持原样；没有发布或提交。

## 修复

`release_content_scan.ps1` 是两条发布入口共用的扫描视图适配器。它仅在指定相对路径
和完整表达式一致时识别 C 的 `ES_PASSWORD` 条件输出以及 PowerShell 的锚定布尔断言。
只替换内存视图中的字段名，保留全部值和相邻文本。原文件不修改，整个文件不会被跳过，
不普遍放行数值密码。识别时输出原因和相对路径；模式、条件、值或路径变化则恢复原扫描。

反例守卫另发现原凭据赋值正则要求至少两个字符，单字符密码、Key 或 secret 会漏检。
两条入口均改为拒绝至少一个非占位字符，原有空值和尖括号占位提示语义保留。
准备脚本在改动 staging 前运行新增守卫，独立审计继续执行二进制、目录、配置、字体许可
和内容检查。秘密正文不进入失败诊断。

## 验证

`test_release_content_scan.ps1` 源链接两套真实模式，读取生产探针/断言，并调用完整审计入口。
覆盖同一行前后及同一文件内的凭据、短值、空值、占位提示、API Key 包含诊断表达式、
其他 token/Bearer/本机路径、修改后的值/条件/路径/锚定、源文件哈希、配置/二进制/缓存排除。

| 检查 | 结果 |
| --- | --- |
| 修复前真实审计夹具 | 退出 1，复现两处探针误报 |
| Windows PowerShell 5.1 | 56 项通过，包含真实审计入口与两套模式反例 |
| PowerShell 7 | 56 项通过 |

| 最终源码目录独立审计 | PowerShell 5.1 和 7 均退出 0 |
| 完整产物指纹检查 | `verify_build_artifacts.ps1 -RequireComplete` 退出 0 |

本项不改编译输入，沿用此前完整构建与运行时验证；最终只读核对产物指纹，并对准备出的
源码目录重新执行内容审计。源码准备会包含新增扫描 helper 与守卫，不携带 Unity 引用缓存。

原始日志、独立审计退出码及最终 `verification.json` 保存在本地
`.scratch/release-content-scan-2026-11-06/`；此前 Unity 验证账本保留为历史记录，其中的
源码发布阻碍已由本记录取代。

## 边界

只对两处已知非秘密表达式作窄范围识别；这套启发式发布扫描不能保证发现所有形式的秘密。
本次没有新增全文件白名单、关闭凭据规则或更改运行时协议。源码审计通过也不代表已经完成
程序发布、远端上传或游戏实机验证。
