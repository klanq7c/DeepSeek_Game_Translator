# Ren'Py 字体兼容：保留游戏选择，按中文片段补字

日期：2026-10-31。影响范围：Ren'Py hook/rendering、真实引擎夹具及共享服务器契约守卫。没有修改共享服务实现、翻译记忆、游戏文件或存档；这份记录属于开发验证，不是发行说明。

## 复现与根因

原 `_ds_apply_font` 将全部样式字体改成部署的 Noto CJK，并为发现的所有字体写入四种粗体/斜体全局替换。FontGroup 的范围选择、remap、原有映射因此可能被绕过。Noto CJK 不包含测试使用的私用区图标及 U+1F600，统一替换会丢字形。

修正此前测试夹具的版本 API 差异后，Ren'Py 7.8.7 和 8.1.1 均稳定复现：FontGroup 样式和字体替换表被覆盖；图标、remap、emoji、粗体替换、拉丁字形、内联字体/别名像素与直接加载游戏字体得到的参考图不同。普通中文参考图仍通过，因此失败不是整个绘制流程失效。

分段补字的初版还暴露了附标问题：中文后的变体选择符、组合附标被拆到正文原字体。Windows Python 2 将补充平面字符表现为两个 UTF-16 代理项；仅按单个 `ord()` 判定会漏过补充平面汉字和 IVS。新增失败守卫后修复，并额外检查相邻 emoji 与汉字具有相同低代理项时不会串用字体。

## 实施与所有权

1. `_ds_apply_font` 串联现有 `TextSegment.subsegment` 和 `FontGroup.segment`，引擎继续负责字体变换、分段属性复制和后续 `font_replacement_map`。不重新实现引擎的整套样式/排版流程。
2. 普通字体只在中文及相应标点片段使用部署字体；拉丁字符、图标和 emoji 留给原字体。FontGroup 先按原 remap 语义检查目标，只为未明确分配字体的中文片段补字；明确范围及非中文片段继续调用原方法。原样式、组、remap、别名与替换表不变，也不建立持有游戏对象的缓存。
3. 中文补字后的变体选择符及组合附标跟随基字。文本按 Unicode 标量边界切片，保留 Windows Python 2 的完整代理对，不把临时字体分配写入组的码点表。
4. 线程局部上下文仅在创建/推进原分段迭代器时有效，生成器暂停后立即退出；异常与关闭不遗留状态。游戏原方法错误和缺失非中文范围错误继续传播。直接调用原 FontGroup 不凭空增加中文范围。
5. 删除字体清单枚举、全局字体覆盖和语言切换回调；后续排版自然读取语言切换后的真实样式。不增加网络请求，也不把显示补字记录为成功翻译。

字体策略仍有明确范围：它不是任意字体的 cmap 缺字检测器。游戏显式 CJK 范围不会被覆盖；该字体缺字、部署字体缺字、第三方完全替代基础分段流程的特殊渲染器，仍需要各自的运行时证据。每次真实排版增加字符分类工作，没有实机 profiling 或 FPS 改善结论。
