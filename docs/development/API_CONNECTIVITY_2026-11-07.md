# API 配置连通检测（2026-11-07）

范围：启动器 API 配置窗口；C 与 C# 镜像同步。版本为本地开发版 0.4.1.1，未发布。

本文记录首次实现。随后根据本机 Ollama 首次加载的实际超时修复了响应等待，见 [本地模型首次加载修复](API_LOCAL_STARTUP_2026-11-07.md)。

## 行为

- 新增“检测连通”及独立结果区域。一次短的非流式聊天 POST 使用当前表单快照，包括未保存的地址、模型和 Key；不调用本地翻译服务，不写配置或翻译记忆。
- 只有完整、有效的聊天响应包含非空正文才报告成功。认证、权限、接口或模型地址、代理、限流、服务端错误、超时和响应格式失败均有对应诊断；日志不包含 Key 或响应正文。
- 保留现有模型选择与目录刷新。检测不替换模型 ID，不自动保存；界面提示可能产生少量费用。
- 后台任务不访问窗口。表单变更使旧结果失效，关闭窗口释放 UI 的任务引用；剩余请求结束后自行释放资源。
- 使用有限的传输等待及响应体大小/读取时限；WinHTTP 的超时为分阶段超时，不宣称统一总时限。参见 [Microsoft WinHttpSetTimeouts 文档](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpsettimeouts)。

## 验证

- 完整 `build_native.bat` 退出 0，244 个源码与测试输入无构建期间漂移。
- 新增本机假提供商的 44 组 C/C# 实际 HTTP 检查：正常、分块、EOF 分帧、空 Key、模型原样传递/转义、401/403/404/407/429/5xx、重定向、无效 UTF-8/JSON、空正文、推理正文、截断、超大响应、非法配置和超时。已加入构建门禁。
- 启动器 parity 284 项通过。配置窗口登记 14 个控件，检查草稿变更/改回后的过期结果、缺少模型/Key；96/120/144/192 DPI 的实际控件布局与 C/C# 位图一致。
- 真实桌面检查：两版按钮均成功调用本机假提供商；C 版还检查了 HTTP 401 提示、检测中关闭后重开不接收旧结果。实际屏幕下卡片和按钮无遮挡。
- 两份隔离夹具的 `api.ini` 内容保持不变。未使用真实账号、真实游戏或用户翻译记忆。
- 界面检查末尾用户按 Esc 停止自动操作，随即停止；C# 测试窗口可能仍打开。
