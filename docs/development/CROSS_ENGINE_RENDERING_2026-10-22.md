# RPG Maker 汉化经验在其他引擎中的应用（2026-10-22）

版本基线：0.4.1.0 工作区。本次为本地修复与核查，不代表发布新版本。

影响范围：Godot 3/4 运行时、Unity Mono/BepInEx 5/6 显示适配，以及相邻引擎回归守卫。

## 可以复用的原则

| RPG Maker 中暴露的问题 | 跨引擎要求 | 具体实现归属 |
| --- | --- | --- |
| 自定义窗口绕过普通文本入口，造成漏译 | 按实际绘制入口检查文本覆盖范围 | 各引擎插件与显示生命周期 |
| 整页纯文本缓存覆盖有颜色的对话 | 校验格式来源，保留游戏当前标签、参数和控制符 | 显示适配层，不能全局清洗翻译记忆 |
| 游戏重绘把中文覆盖回英文 | 在已有生命周期内重用缓存，同时保留当前颜色、字号和交互目标 | 各引擎刷新与主线程边界 |
| 标签或样式把一个词拆成多个查询 | 先确定语义文本，再映射回原来的格式片段 | 引擎自身的分词、标签和控制符规则 |
| 新页面被旧请求的结果覆盖 | 核对当前文本和对象，未完成响应不能降级已有成功译文 | 异步结果发布与显示对象所有权 |
| 测试用固定成功结果代替关键显示逻辑 | 测试必须执行实际决策和调用链 | 生产方法源链接或真实引擎夹具 |

图片文字识别的筛选、异步排队和结果归属可以借鉴；RPG Maker 的位图入口、坐标、字体度量和窗口换行不能直接复制到 Ren'Py、Unity 或 Godot。本次没有扩展其他引擎的图片 OCR 功能。

## 实际发现与修复

### Godot：外部译文带入新的 BBCode

运行时已将原始 BBCode 拆成标签与可见文本，只请求可见文本。但响应回调此前会把任何非空的新字符串写入显示缓存。迟到的 `[color=white]…[/color]` 可覆盖已经安全的译文，在后续重绘中强制改变游戏当前颜色；新增链接也有同类风险。

Godot 3/4 的响应边界现拒绝新引擎标签、带参数或成对的自定义效果，记录 `batch-markup` 并沿用未命中退避。已经成功的安全缓存保留；初次不安全结果不作为成功译文。规则与资源补丁层的标签识别范围一致，保留中文括号、`[Esc]`、`[Ctrl]`、`[F1]` 等字面提示。有效的后续结果仍可恢复显示。

拒绝发生在 Godot 本地显示缓存入口；共享缓存原文和译文均不改写。如果外部持续返回不安全结果且没有安全命中，控件仍显示原文，日志明确说明原因。

### Unity Mono：长对话与多行对话被清掉格式

`ShouldPreserveRichTextForDisplay` 以前仅按短 UI 文本规则决定格式是否保留。即使原文和译文的粗体、斜体、字号标签完全相同，超过 36 字符或含换行仍会进入去标签分支；已有中文对话也受影响。

现先比较原文和译文的有序标签（包括属性和链接标识），完全一致时保留格式。其他情况继续使用既有兼容规则。修改适用于同源构建的 BepInEx 5/6，不改变公共服务、字体规则或缓存内容。

测试原先把格式判断替换为固定成功，无法发现该缺陷。本次将真实格式判断、标签匹配和去标签逻辑接回 TMP/UGUI setter 夹具。新增用例先复现 3 项失败，再验证修复，同时保护原有动态颜色、未命中去抖和非标签尖括号文本。

这项修复针对格式完整的文本。外部译文丢失内部标签、改变颜色属性等其他情况没有因此获得通用重建能力，不能把本次结论扩大为任意富文本均可恢复。

### Ren'Py 与 Unity IL2CPP

- Ren'Py 已有变量/标签保护、引擎文本分词边界、主线程刷新和迟到未完成响应不得覆盖成功缓存的保护；本次相邻边界守卫通过，没有为追求代码一致而复制 RPG Maker 实现。
- Unity IL2CPP 的已构建 XUnity 端点与 TMP 回退守卫继续保护动态颜色、链接属性、标签内部标点和叠加层颜色/透明度；本次没有修改其生产代码。

## 同日复查与补充修正

用户要求检查改动是否引入问题后，补查此前未覆盖的边界，复现并修正三处问题：

1. **Godot 字面按键提示误拦截。** 新增标签判定把名称转成小写、截断空格后的内容，会把 `[B]`、`[I]`、`[U]`、`[b option]` 误当内置格式。真实 Godot 3.6/4.3 的 RichTextLabel 将这些内容按字面显示。现按完整且区分大小写的内置标签名称判断；带参和成对自定义效果保护继续保留。
2. **Unity 标签比较截断带引号的属性。** 新增的有序标签判断直接使用正则匹配结果，遇到链接参数中的 `>` 会过早截断，使不同链接参数被误判为相同格式。现使用已有 `TmpRichText.TryGetTagEnd` 获取完整标签边界，逐字比较整个标签及属性；未能确认完整边界时沿用既有兼容判断。
3. **Unity 格式保留与旧清理逻辑相互影响。** 长对话的新保留路径会经过旧的破损标签修复，合法链接标识内的 `size=20>`、`color>` 等内容可能被错误插入 `<`。现清理前保护完整标签、结束时原样恢复，避免这些属性被当作裸标签。真正的嵌套闭合残片、破损字号、结尾斜杠仍按既有规则修复；内部占位串避开原文且不会进入最终显示或缓存。

测试现继续源链接真实组件准备、格式清理、标签过滤和富文本属性设置，减少先前测试中“已保留格式便直接返回”的模拟。Unity 108 项通过；新增双引号/单引号链接参数检查、实际 setter 准备链、旧修复行为及字面文本保护。Godot 四种运行组合均通过，字面括号同时核对真实引擎解析结果和正式响应回调。两版 Unity 插件共用同一修复，Ren'Py/RPG Maker/IL2CPP 继续作为相邻回归边界。

补充修正后，脚本检查 124 项、两版服务器契约合计 152 项通过；完整构建及产物核验通过，本地程序已更新。启动器一致性仍为 263 项通过、13 项因已有服务占用 19999 跳过，Unity HTTP 预热及服务生命周期同样跳过；现有服务未被停止。真实 Ren'Py 运行时与 Unity 完整游戏游玩仍未执行，上述模拟边界没有扩大为整游兼容性结论。

## 再次复查：完整标签在不同处理阶段的边界

影响范围限定为 Unity Mono/BepInEx 5/6 的显示与发送前保护，不更改共享服务器、缓存格式或其他引擎的标签语法。

前次修复让格式比较和清理识别完整带引号标签，但纯文本降级、UGUI 不支持标签的过滤、可见文字提取以及发送前 token 保护仍使用直接正则替换。对于 `<link="quest>original">`，这些阶段只处理到引号里的第一个 `>`，会把 `original">` 当作正文显示或发给模型。测试通过实际 TMP/UGUI setter、无富文本能力的组件准备和生产保护链，先稳定复现 10 项失败；双引号与单引号均受影响。不是完整标签清理或外层格式恢复导致的残留。

`ReplaceRichTextTags` 现先沿用已有已知标签筛选，再使用显示层现有解析器确定完整边界。上述阶段使用同一边界；未能确认完整标签的既有宽松/残片语法继续使用原识别范围，不扩大标签集、不新增静默错误回退。标签参数不进入可见正文，完整标签仍按原值保存与还原，UGUI 继续保留支持的粗体、移除不支持的链接。

Unity 129 项通过，覆盖属性含 `>`、`<br>`、`<color=red>`、标点和裸闭合片段，发送前保护及完整还原，实际换行与普通尖括号文字；保留此前长对话、动态颜色及损坏标签修复检查。相同带引号链接通过已构建 IL2CPP 端点，继续保护相邻行为。脚本 124 项通过，包含真实 Godot 3.6/4.3 的 autoload/sidecar 夹具，以及 RPG Maker/Ren'Py 相邻边界。原始失败与成功日志留在本地 `.scratch/`。

## 再次复查：Godot 预检进程结束归属

影响范围为启动器 Godot 自动加载预检；C 与 C# 同步修改。完整构建中的原有提前崩溃集成断言复现差异：进程输出加载证明后自行退出，C 仍确认成功。仅重新检查句柄存活不足以消除窗口；Windows 可能接受对正在退出进程的结束请求，最终却保留自行退出码。过去父进程使用结束码 1，也无法与该类失败区分。

收尾现使用专用结束码，等待进程结束并读取最终退出码。只有父进程实际发起结束、最终退出码匹配且已有完整加载证明时才缓存成功；任何自行退出，包括退出码 0，均不确认。预检签名升级，避免沿用此前可能误判的结论，不修改用户配置或翻译记忆。

集中进程检查另复现了退出清理尚未完成时先拒绝结束请求的窗口。现在拒绝后也等待真实退出事件，沿用一秒收尾期限；仍未退出则保留原始错误，不用固定睡眠或重试掩盖状态竞争。13 种确定性时序检查源链接两版真实代码，保护接受停止后崩溃/零退出/查询失败、专用码却未由父进程结束、拒绝停止后的延迟退出信号等边界。原有集成断言保持不变。

最终验证：C 与 C# 启动器各连续执行 30 次真实提前崩溃进程探测，全部拒绝确认加载。完整 `build_native.bat` 重新执行并记录退出码 0，内嵌产物核验通过，Unity 契约 129 项、启动器一致性 277 项、进程时序 13 类均通过。最后一次构建时端口 19999 已空闲，补跑并通过此前跳过的 Godot 补丁包、Unity HTTP 预热（46 个场景）和服务生命周期（10 项）检查；构建中的共享核心、缓存持久化、响应缓冲、模型目录及两版服务异常请求/并发/超时边界均通过。本地启动器已重新生成，未发布到远端。

脚本检查沿用本轮的 124 项通过结果（含真实 Godot 3.6/4.3）；本次未改脚本，未重复执行。真实 Ren'Py 7/8 运行时未配置，Unity 完整游戏游玩未执行。上述结果仅涵盖已执行的检查，不等于所有游戏均无兼容性问题。中断构建、最初失败、集中复现及最终成功日志保留在本机 `.scratch/`。
