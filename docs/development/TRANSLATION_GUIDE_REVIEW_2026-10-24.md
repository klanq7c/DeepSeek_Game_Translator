# 汉化经验核查与通用改进（2026-10-24）

本轮结合两份 Ren'Py 汉化经验和一份 Unity 实战记录检查现有翻译器。
影响范围为启动器 Ren'Py 源码预热、Ren'Py 运行时发现与字体生命周期、
Unity Mono/BepInEx 5/6 和 IL2CPP TMP 字体显示层。共享翻译记忆与服务器协议不迁移。

## 经验如何应用

| 经验 | 核查结论与处理 |
| --- | --- |
| 编译脚本与源码不应混为一套标识 | 从原引擎已加载的翻译块读正文及原生标识，不反编译或重编译用户脚本。已有语言翻译块优先。 |
| 字面量解码决定缓存是否命中 | Ren'Py 源码预热单独处理空白折叠、raw、字面括号、转义及默认三引号独白；Godot 仍使用原字符串解析器。 |
| 名字与菜单有独立通道 | 编译清单补充 Say/TranslateSay 正文、显式字面说话人及静态 Character 名字；菜单与现有实时钩子继续保留。 |
| 切换语言会重建样式 | 在 `change_language_callbacks` 中恢复已部署 CJK 字体；字体清单包含子目录与归档内的内联字体。 |
| Unity 显示名可能也是逻辑键 | 继续在文本组件/渲染边界显示译文。未新增 ScriptableObject 字段改写或 `.assets` 写入器。 |
| 字体缺源与静态图集不能混用 | 保留预制 TMP 字体的 population mode，先只读检查自身字形，再按模式决定能否动态加字。 |
| 对账必须检查真实键与原文件 | 预热守卫检查键内容、顺序和 C/C# 请求一致性；真实 Ren'Py 夹具检查原 `.rpyc` 字节不变。 |

## 不直接照搬的部分

- Ren'Py 对白标识不是通用的“每个 Say 一次 MD5”或“只按位置计算”。原生翻译块、显式 ID、替代标识及版本规则都需要保留。
- 同一语言重复的 `old` 不是可靠的覆盖机制；不能据此生成冲突翻译文件。
- 弯引号/标点归一化只能用于诊断候选匹配，不能为某个引擎改写共享缓存键。
- 不按游戏专有变量名改写性别代词，不强制修改语言偏好；这些行为可能改变游戏逻辑或用户选择。
- `--count` 的缺失统计不等于语义翻译质量，也不代替实际运行检查。
- Unity 某个版本、某个对象的资产损坏经历，不能推出所有 UnityPy 写入都不安全或所有反射字段布局都能直接用来序列化。当前通用工具没有新增此类写入。
- 保持现有经过审查的字体与许可，不因某个样本改用其他字体来源。

## 已复现与修复

### Ren'Py

旧预热器按物理行搜引号，空白/转义结果与引擎不同，忽略独白，且误收集注释、
Python 返回值、字体和样式字段。新词法层先定逻辑语句边界，再判断可见正文。
修复同时覆盖 raw、连续空格、反斜杠后的连续空白、字面括号、Unicode、
首尾空格、CRLF、字体标签以及含下划线变量的对白。

目录递归不再以父目录存在 `.rpy` 为前提，避免只在章节子目录保留源码时漏扫。
运行时从原编译翻译块补充对白和静态名字，在主线程形成有界字符串快照；
HTTP 工作线程不再遍历游戏 AST，也不求值游戏表达式。

真实引擎夹具首先复现了切换语言后默认 CJK 字体消失。恢复逻辑移入语言变更回调，
同时覆盖已枚举的内联字体资源。保留原语言选择和故事变量。

源码扫描仍是预热补充，不是完整 Python/Ren'Py 解释器：自定义独白分隔符、
动态文本表达式和自定义语句由原引擎运行时发现，不宣称静态提取完备。

### Unity

原 IL2CPP 加载器强制将预制字体改成 Dynamic，加字入口没有先确认已有覆盖；
静态图集或无源动态字体会走到不必要或必然失败的原生加字入口。
两条加载路径现在都保留打包模式。

Mono 与 IL2CPP 共用显示层 `TmpFontPopulation`：只查本图集，不递归回退，
不隐式加字；已有覆盖直接成功，静态缺字仍失败。Dynamic 缺少 Font 和路径时
记录诊断并保留显示回退；DynamicOS、路径字体、旧 API 与后续补入源字体继续可用。

IL2CPP 的预热样例不再预填“已覆盖”集合，覆盖记录随加载的字体重置。
一次正常的原生失败不再换等价重载重试；非布尔结果不能伪装为加字成功。

## 同日复查：屏幕表达式、已有字符串翻译与图集重置

扩展原夹具后复现并修复了三处边界问题：

1. **屏幕文字的词法规则不同于对白。** SL2 屏幕参数是 Python 表达式，普通空格不能按 Say 折叠，`\x`、八进制、`\U` 和未知反斜杠转义也不能沿用 Say 解码。两版启动器同步分开处理，保留真正的输入提示；变量正文后的 style 字符串和仅在代码字面量中提及的 `renpy.input` 不采集。动态拼接/格式化、命名 Unicode 和版本相关的 raw Unicode 留给对应引擎发现，不能猜一个缓存键。
2. **菜单和名字还需读取已有字符串翻译。** 原清单只选择原生对白块，漏掉了菜单、显式名字和静态 Character 名字的字符串层。现在按当前语言只读该层及 `{#context}` 匹配，不求值故事表达式。不能直接调用 `translate_string`：引擎开启更新翻译模式时，该函数会登记未知字符串并最终写回文件。真实 7/8 夹具另外保护更新模式下的翻译表和 unknown 集合不变。
3. **已覆盖不等于图集永远有效。** 游戏可清空同一个 TMP 字体的图集；IL2CPP 旧集合仍会对已见文字返回成功。现在每次先只读检查当前图集，确认丢字后清除相关旧记录并尝试补字；补字后请求刷新网格。已有覆盖的 60 次重绘不重复动态加字或反复刷新网格。旧版缺少查询 API 时保留原有成功加字记录，并明确诊断无法确认当前覆盖的限制。

已有字符串翻译的修复位于运行时清单和菜单预取边界。启动器的源码预热不读取用户语言偏好，
仍可能预取一些原始英文；不能据此宣称整个游戏没有额外预热请求，原生译文的显示也不由该清单改写。
