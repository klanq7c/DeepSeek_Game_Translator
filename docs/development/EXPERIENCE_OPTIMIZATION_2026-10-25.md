# 多引擎汉化经验复用（2026-10-25）

基于用户提供的多游戏实践总结，核对本地 0.4.1.1 开发工作区。
后续发现及修复的边界回归见 [经验优化复查](EXPERIENCE_REGRESSION_2026-10-25.md)。
本轮影响范围：Ren'Py 7/8 hook、Unity IL2CPP/TMP 字体显示层、
Godot 启动器资源预热及其 C# 镜像。公共 API、共享缓存键和用户数据格式不迁移。

## 经验筛选

| 经验 | 处理 |
| --- | --- |
| 标签、占位符、内部标识必须原样保留 | 扩展 Ren'Py 正式响应恢复链的完整性校验，保留原始名字、长参数和标签顺序。 |
| 全角标点独立行也需要字体覆盖 | 补齐 IL2CPP 字体入口；语言判定与字体需求分开，富文本属性不算可见字形。 |
| 压缩 GDSC 不能在压缩字节中搜明文 | 识别 tokenizer v100 的非零解压大小，拒绝把该载荷当文本，并按扫描操作报告一次限制。 |
| 以原文为键、去重、原子写入、补丁化交付 | 延用现有原文键、缓存持久化与部署所有权机制，没有新增按行号回填或资产写入。 |
| 固定游戏的路径、存档值、语言预设和资产格式 | 保留为调查依据，没有推广为强制切换语言或改写故事变量的通用规则。 |
| 字体子集化 | 通用实时翻译器无法预知后续译文、输入和角色名；保留现有字体来源及覆盖方式，没有改成固定游戏字符子集。 |
| UE4 locres/pak 补丁 | 当前项目的四引擎适配范围没有因此扩大，未声明新增 Unreal 支持。 |

## Ren'Py：完整标签与旧式占位符

原片段收集器最多读取 64 个、每个最多 96 字符。超过该边界的标签、链接参数或
插值会绕过计数和恢复；空标签与未闭合标签也可能直接进入早期对白输出。
新守卫在原实现复现了八个失败断言，包括新增伪标签、长链接改变、尾部标签及旧式变量。

收集与恢复现在检查完整片段，不截断长参数或尾部标签；新增、缺失、未闭合的
片段保留原文并记录诊断。旧式 `%(player)s` / `%(score)03d` 在启用
`old_substitutions` 时按位置还原原始映射字段，普通字面百分号仍使用原显示转义。
校验异常返回原文，不能把未验证结果记为成功译文。

安全的双开括号字面量继续允许，原自定义标签和错拼资源标识保持原样。
校验没有改写公共翻译记忆，只影响当前 Ren'Py 响应接受和显示。

经验总结中关于 `replace_text` 阶段的说法不能直接推广。官方回调在插值及标签拆分后
接收可见正文；项目可以另有包装。需要保留插值模板时，应使用对应的早期边界，
不能假定所有回调都持有 `[variable]` 原文。[官方配置说明](https://www.renpy.org/doc/html/config.html#var-config.replace_text)

也不能仅凭松散源码与归档内编译文件并存就断言双重加载；正常 Ren'Py 工程本来会同时
拥有源码和编译产物，应按逻辑路径和原生标识检查。此次继续只读原游戏文件。

## Unity：字体需求与语言判定分开

Mono 已覆盖 U+3000–303F 与 U+FF00–FFEF；IL2CPP 的字体入口只认汉字范围，
导致 `「」【】` 这种整行标点没有进行字形检查。

新增 `NeedsCjkFont` / `IsCjkFontCharacter`，用于 UGUI、TMP 字体应用、
TMP→UGUI 显示回退及图集预热。富文本模式跳过完整标签参数，纯文本模式仍检查
看起来像标签的字面文字；长链接内的中文不能触发字体切换或进入请求字形集合。
原 `ContainsCjk` 的语言语义及现有标点降级偏好保持独立，未修改服务器准入规则。

静态覆盖、缺字失败、同一字体图集清空后的重查、稳定重绘以及 Mono 相邻行为
继续由实际方法的源链接夹具保护。没有新增字体、修改字体许可或改写 `.assets`。

## Godot：压缩容器不能伪装为明文提取

官方 tokenizer v100 头部在偏移 8 记录解压大小，非零时载荷由 Zstd 解压。
现有启动器没有该解压器；旧二进制扫描会把可打印载荷片段当候选文本。
PCK 夹具已在两版实际预热入口复现此问题。

现在识别该压缩容器并跳过原始字节扫描，同一次发现只输出一次说明。
相邻场景、旧 GDSC 和其他资源仍使用原路径，PCK 只读且哈希不变。
**本轮没有新增压缩 GDSC 解压或回填能力**，其可见文字继续由现有运行时发现；
不可见内容可能稍后才进入翻译队列，不能声称已完成预热。
[Godot 官方格式实现](https://github.com/godotengine/godot/blob/4.4/modules/gdscript/gdscript_tokenizer_buffer.cpp)

## 验证

完整构建发现并复现了独立的 Godot autoload 预检竞争：单独 ready 之后立即退出时，
父进程可能先停止探针，导致两版结论不同。新增凭据守卫在旧解析器出现四个失败场景。
现在只有 ready 后读取专用 stdin 并输出 ACK 才允许确认；输入在创建子进程前预写，
关闭写端，不通过延迟猜测子进程未来状态。原有专用结束码与退出检查保留，
`lf_godot_autoload_crashed` 的错误输出和失败断言没有改动。
来源指纹同时升级到 `DST_GODOT_SOURCE_V5`，旧 V3/V4 来源标记都要重建，
避免生成器升级后复用没有 stdin 握手的旧包；用户原始 PCK 不参与改写。
后续更改生成器协议时须同步升级来源标记和预检签名；只对外部脚本做哈希，
无法覆盖生成器内联文本的变化。

实际 C/C# autoload 生成器在两种引擎下输出一致；真实 Godot 3.6/4.3 分别执行
正确输入、错误输入、关闭输入和普通启动，确认普通启动不读取探针输入。
就绪凭据守卫八场景及退出收尾十三场景通过。该协议只证明当前脚本完成握手，
不证明之后游戏不会崩溃。[Godot 3.6 stdin API](https://docs.godotengine.org/en/3.6/classes/class_os.html#class-os-method-read-string-from-stdin)、
[Godot 4.3 stdin API](https://docs.godotengine.org/en/4.3/classes/class_os.html#class-os-method-read-string-from-stdin)。

- Ren'Py 正式函数守卫 9 项通过；真实 7.8.7 / 8.1.1 各执行源码与原编译脚本两阶段，每阶段实际 163 条断言及 60 帧动画通过。真实引擎先确认伪标签非法，再确认正式 hook 保留原文；旧式字段经过实际 Python 格式化验证。
- Unity 契约从本轮基线 204 项扩展到 211 项通过；原生 FontEngine 和对象属性由夹具模拟，不等于实际 Unity 游戏全流程验证。
- Payload 检查最终 128 项通过，已配置真实 Ren'Py 7/8、Godot 3.6/4.3，并保留 RPG Maker 相邻检查。
- Godot 独立 C/C# 探针通过：压缩载荷不进入请求、相邻场景继续提交、每次扫描只记录一次、原 PCK 哈希不变。完整 launcher parity 另登记同一场景。
- 最终 `build_native.bat` 完成，退出码 0；Unity 契约 211 项、launcher parity 281 项均无失败，包含原 Godot 崩溃断言及 V3/V4 包升级。构建的其他缓存持久化、缓冲区、模型目录、服务器边界、混排保护和本地优先门禁全部通过。原始日志保留在本机 `.scratch/experience-optimization-2026-10-25/`，最终完整日志为 `build-verified.log`，脚本日志为 `payload-final.log`。
- 没有运行会停止现有服务器的 `-ServerSmoke`；提供方测试使用本地夹具，不代表真实远程 API 可用性或所有游戏全流程验证。

本轮没有修改用户游戏、存档、语言偏好、配置或翻译记忆，没有发布到远端。
