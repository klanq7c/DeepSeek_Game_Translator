# 模型刷新与官方显示名称

日期：2026-10-14。基于 0.4.1.0 工作区，属于本地开发构建。

## 范围与原因

影响启动器 API 配置与模型目录解析，两种语言实现同步修改。

使用当前配置只读请求 DeepSeek 官方 `/v1/models` 与 `/models`，两者均返回
`id=deepseek-flash`、`name=DeepSeek-V4.1-Flash`。此前解析器只保留 ID，
下拉框也只显示 ID，用户无法从列表辨认该名称对应的当前版本。
本地假提供商复现了“响应包含名称，解析结果丢失名称”的问题；修改前断言失败。

协议依据：[DeepSeek 模型目录](https://api-docs.deepseek.com/api/list-models/)
将 `id` 定义为调用标识，`name` 定义为模型选择器使用的显示名称。
兼容别名以[官方模型说明](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)
为准，不能根据 ID 字面版本推断实际模型。

## 修复

- 保留实时目录中的可选 `name`，下拉项绘制名称和 API ID。
- 控件底层值仍为 ID；选择和保存路径不会把显示名称写进模型配置。
- 状态区显示选中模型的名称，刷新时替换整份目录和名称，即使 ID 没有变化。
- 下拉列表适当加宽，继续随窗口 DPI 缩放。
- 保留已有选择、手工填写、请求失败提示与过期结果拒绝逻辑。
- 不增加固定版本列表，也不修改本机 API 配置、翻译记忆或引擎运行模块。

### 可选名称异常的处理

1. 外部目录的 `name` 可能不是字符串，或包含控制字符、无效 Unicode、超出显示长度。
2. 元数据由厂商提供，本地无法修正其源头；合法 ID 仍是调用依据。
3. 此时仅显示 ID，不能把名称异常伪装成完整元数据，也不删除可用模型。
4. 返回结果、配置窗口状态和启动器日志记录降级数量；不记录 Key 或响应正文。
   缺少可选字段或字段为空属于正常协议行为，不报错。

## 验证

- 模型发现假提供商：98 个场景，C/C# 一致。覆盖官方名称、未来版本、稳定 ID
  的新名称、缺少名称、无效名称诊断、认证、分页、截断响应及失败整份丢弃。
- 控件探针新增名称展示、选择后仍为 ID、刷新名称替换、无名称厂商兼容检查。
- `build_native.bat` 成功，启动器一致性 271 个场景及模型目录等内置门禁通过。
- 实机检查在启动窗口时收到用户 Esc 中止，未完成刷新、展开、选择的桌面操作；
  不将控件探针等同于真实账号的整条界面验证。
- 原始记录位于本地 `.scratch/model-catalog/`。
