# 启动器长路径组件释放与部署还原修复（2026-11-07）

版本：0.4.1.1，本地开发版，未发布。承接同日全程序检查发现的长路径失败。

## 问题与影响范围

安装根目录长 150 字符时，TMP 字体组件目标路径长 263 字符、临时文件长 269 字符；真实 C/C# 启动器均只同步 13/14 个组件并返回 5。较短根目录可同步全部 14 个组件。根目录长 230 字符时，更多中间目录和组件也达到 Win32 的传统限制。

影响范围属于启动器检测/部署/预热使用的共享文件层，以及自有组件同步。没有更改共享翻译缓存、引擎脚本、系统注册表或真实游戏。

## 修复

- `path_for_file_api` / `SafeFs.TryFileApiPath` 在文件 API 边界生成规范化的扩展绝对路径；普通短路径仍使用原参数。
- 属性查询、目录创建、文件读写、复制/移动/删除和枚举共用这个转换，使安全检查与实际操作不会使用不同的路径解释。
- 组件内容比较同步支持长路径，保证第二次运行不重写相同字节或改变时间戳。
- 部署和还原的属性查询、只读属性处理、目录枚举及空目录清理同步经过相同边界。此前 C 版会把实际存在的长路径文件当成缺失，留下 hook 却报告还原成功；C# 的 `PathUtil` 存在性查询没有同步转换，导致有效字体所有权标记被误判为缺失，也影响 RPG Maker 检测。
- 保留原路径缓冲上限及逐级重解析点拒绝。外部设备命名空间、尾点/尾空格、保留设备名和备用数据流不能借转换指向新的对象；独立 `.` / `..` 正常规范化。

依据为 Microsoft 的[路径长度限制](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)及[文件命名空间](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)说明。UNC 仅做语法转换，本轮未连接真实网络共享，也不宣称所有游戏、第三方运行时或系统工具都有完整长路径支持。

## 证据与验证

原始证据留在本地 `.scratch/long-path-2026-11-07/`，完整检查阶段的记录继续保留在 `.scratch/full-audit-2026-11-07/`。

- `test_long_payload_paths.py`：原组件同步反例有 36 项失败；补齐有效 RPG Maker 夹具后，相邻部署/还原另有 7 项失败。最终专项 144 项通过。使用两版真实启动器，组件根目录长 150/230 字符、游戏根目录长 240 字符，包含中文和空格；核对 14 个组件哈希、用户配置/缓存保护、重复运行时间戳、损坏文件修复、目录冲突及长路径 junction。Ren'Py/RPG Maker 覆盖只读文件、旧字节码、重复部署、原备份、完整还原和修改后字体保留；Unity 覆盖长 payload 与安装目录的逐文件验证、递归删除、空目录清理及用户修改/新增文件保留；Godot 覆盖补丁还原和原项目/包不变。
- `test_file_api_paths.py`：C 源链接生产文件层，C# 调用当前启动器实际实现；26 项边界检查通过，PowerShell 5.1 和 7 均执行。尾点测试先出现两项失败，补上转换前歧义组件拒绝后通过，没有放宽断言。
- 稳定修订的 `build_native.bat` 完整重建退出 0，238 个构建输入前后 SHA-256 无变化；此前混合修订构建单独保留，不作最终证明。五个 Unity 托管组件均重新构建，启动器一致性 284 项、共享核心 132 项、Unity 端点 247 项、缓存持久化 103 项、缓存解码 260 项、RPG Maker 命令字段 40 项及长路径 144/26 项等内置门禁全部通过。
- 当前两版服务重新执行真实 HTTP 契约：160 项通过；使用自有动态端口与假提供商。脚本套件 130 项通过，配置并运行 Ren'Py 7.8.7 / 8.1.1 与 Godot 4.3 实际引擎夹具；Godot 3 本轮未重测，保留之前系统 DLL 崩溃的未解决边界。
- 改动的 `fsutil.c`、`self_update.c`、`deploy.c` 执行 GCC `-fanalyzer`，均退出 0 且无诊断。PowerShell 5.1 完整构建之外，当前 C# 产物也通过 PowerShell 7 的 26 项文件 API 边界检查。
- 当前程序的隔离打包检查仍为 18 项通过、2 项失败：仅当前版本 Release 链接与文档下载文件名不匹配。0.4.1.1 是未发布开发版，README 仍指向已发布 0.4.1.0；未改成虚假链接、未放宽检查，也未发布隔离生成的附件。
- 最终产物核对、源码准备及哈希台账见本地 `verification.json`；当前程序和源码必须与该记录逐项相符。

本修复不解决 Godot 3.6 在系统 `wintab32.dll` 中退出崩溃，也不将未发布开发版的打包文档检查失败当成正式发布成功。

长路径支持的证明范围是上述共享文件操作、组件释放和部署/还原夹具；并非所有启动参数、系统配置 API、引擎资源扫描器或第三方运行时都已取消长度限制。Unity 夹具是启动器文件操作验证，不是 Unity/IL2CPP 游戏内执行证明。未连接真实提供商或网络共享，未修改真实游戏、用户配置/翻译记忆、系统 DLL/注册表，未停止用户服务。
