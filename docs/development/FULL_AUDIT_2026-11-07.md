## 已复现与修复

### 1. 损坏缓存覆盖正确译文或破坏响应编码

影响范围：共享本地服务器/API/缓存，四引擎共用。

- 原 C Base64 解码跳过非法字符、容忍缺失填充；解码后的 NUL 被 C 字符串截断，使损坏键与既有键碰撞，或者把半截译文覆盖到正确记录上。无效 UTF-8 还可能进入 HTTP 输出。
- 原 C# 文件读取接受 NUL，并将坏 UTF-8 替换为字符；这与 C 文件格式的可往返要求不一致。C# API 也能持久化 NUL。
- C 逐行读取原来使用 `fgets` 后的 `strlen`；原始 TSV 中的 NUL 会掩盖换行，并连带消费下一条有效记录。

修复：两版严格接受完整 Base64、有效 UTF-8 和无 NUL 文本，C# 入库另拒绝孤立代理。C 使用加载器拥有的字节缓冲按实际长度寻找换行。损坏记录只跳过自身并限频记录 `load-record-invalid`；不覆盖先前的有效值、不修补内容、不重写原文件。

证据：`test_cache_decode.py` 在修改前出现 16 项失败；原始 NUL 行另有独立失败记录。最终专项 260 项全部通过，覆盖四引擎标记、多行、制表、100 组固定种子 Unicode 向量、64 KiB 分块与未换行尾部。共享核心另有 NUL/孤立代理准入守卫。

### 2. RPG Maker 事件属性顺序导致漏读和误收集

影响范围：启动器 RPG Maker MV/MZ 资源预热；C/C# 镜像同步。

原扫描器假定 `code` 先于 `parameters`，并跨对象保留上一个命令码。JSON 属性重排后，正常对白可能丢失，注释可能被误当对白；嵌套元数据也可能覆盖命令码。PowerShell 7 的现有审计夹具首先暴露此问题，独立真实启动器反例随后复现 8 项失败。

修复：按对象保存字段，在对象闭合后配对自身的 `code` 和 `parameters`；参数值单独跳过，避免内部数据污染外层命令。正常 101 说话人、连续 401 多行、102 选项和 405 滚动文本保持原行为。损坏参数和深度上限有可见诊断，见 `FAILURE_TRANSPARENCY.md`。

证据：`test_rpgm_command_fields.py` 检查六种属性排列、对象隔离、只读文件、完整 C/C# 输出一致性及异常诊断，共 40 项通过。PowerShell 7 的 `test_game_audit.ps1` 随后恢复通过，138 个精确原文键完整。
