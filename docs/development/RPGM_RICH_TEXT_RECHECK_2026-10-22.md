# RPG Maker 富文本修复复查（2026-10-22）

影响范围：RPG Maker MV/MZ 显示适配及其内嵌载荷。本次为本地修复，不代表发布新版本。

## 复现与处理

- 紧凑行距下，引擎文字包围高度与插件行距不同，旧代码用高度相除向上取整，把单行算为两行。现在在自动换行状态内记录实际换行次数，并沿用插件行距；普通窗口、消息行高仍交给原引擎。
- MZ 独立文本状态使用 `startX`、`width`，原逻辑只看 MV 的 `left` 和整个窗口宽度，窄栏可能越界。现在读取对应状态的起点与宽度。
- MZ 的 `drawing=false` 状态用于测量完整文字宽度，原逻辑会提前折行，得到偏小宽度和偏大高度。测量仍可使用缓存译文，但不加入显示换行或显示目标标记。
- 复制的 `drawTextEx` 入口绕过了嵌套翻译抑制，插件内部测量片段会被排队。该入口现在与普通入口共用显示翻译边界，外层文字已处理时不再翻译内部测量片段。
- 带参自定义指令若以字体开关名开头，会被错误拆开；未知指令也可能被无格式整段译文移除。带参指令现在按完整名字保护和分段，字体、变量与插件控制符共同参加有序安全检查。保留 YEP 字体开关紧贴英文的已有语义。

## 回归与边界

- `test_rpgm_rich_renderer.js` 增加六个失败后转绿的用例，覆盖单行/多行/显式换行、MZ 测量与偏移窄栏、复制入口嵌套测量、插件指令分段和无格式缓存拒绝。
- MZ 夹具补齐 `startX`、`drawing`、输出宽高字段；不把提交空缓冲当成可见字形。原有颜色、暂停、字体、排队、存读档与相邻引擎脚本守卫继续运行，脚本检查 124 项通过。
- 本机实际 MZ 的 15 个渲染方法在隔离环境运行四个对应场景，通过宽度、位置、行数和颜色断言。实际 MV 任务/消息插件回放继续验证正文译文、两种颜色、60 次重绘稳定和迟到的无格式对话译文。
- 上述回放替代窗口、输入和 GPU 边界，不等于完整游戏游玩。未配置 Ren'Py/Godot 实际运行时的检查明确提示缺口。
- 完整 `build_native.bat` 通过，启动器一致性 263 项通过、0 失败；13 项因已有服务占用 19999 跳过，服务生命周期和 Unity HTTP 预热检查也明确跳过，原有服务继续运行。其他共享核心、Unity、缓存和构建内置门禁通过。
- 构建产物核验通过，两版启动器内嵌当前钩子；游戏补丁与源码字节一致，部署后实际 MV 回放通过，7 个原始插件/入口/存档文件的摘要不变。原始输出留在本机 `.scratch/`，不包含在源码或玩家下载包中。

共享服务、缓存格式与用户翻译记忆不作修改；实际游戏仅更新翻译钩子。测试使用合成文本，实际游戏代码和本机路径不进入正式测试。
