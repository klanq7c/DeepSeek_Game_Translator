版本：0.4.1.1，当前未发布工作区。本轮从落盘源码、实际程序与旧验证记录开始核对，再审查共享服务器、API 配置、启动器和四引擎适配。原始证据保留在本地 `.scratch/full-audit-2026-11-08/`，不进入玩家下载包。

本报告记录本轮发现与修复的缺陷，不将全部问题归因于最近的 API 连通检测改动，也不构成所有游戏版本和剧情分支无缺陷的证明。

## 已复现的问题和改动范围

### 1. 批量请求误删不同的前文

影响范围：四引擎共用的 C/C# 本地服务器及提供商请求构建。

中英混合原文中的中文会先被保护标记替换。两条不同的前文可能得到相同的保护字符串，原逻辑用该字符串去重，导致本应发送的前文被误删。C 版还会在首个前文为空时重复发送相同的相邻原文，与 C# 不一致。

修复在保护前用原文判定是否重复；请求的中文保护和结果恢复保持原规则。`test_context_dedup.py` 使用两版真实服务和动态端口假提供商，直接核对请求中的上下文位置。修复前 12 项中 6 项失败，独立候选程序修复后 12 项通过。

### 2. Ren'Py 嵌套变量恢复不完整

影响范围：Ren'Py 显示适配层。

`[stats[player].name]` 原先只保护到内层第一个 `]`，译文中的属性名可能残留。合法原表达式在真实 Ren'Py 7.8.7 和 8.1.1 可执行，旧恢复结果分别触发 `SyntaxError` 和 `AttributeError`。

`_ds_renpy_span_end` 现在根据引擎实际的旧 Formatter / 新 substitutions.parse 入口识别完整插值，处理嵌套、引号、切片、括号及格式后缀。源链接与真实引擎测试覆盖转义开括号、未闭合表达式、第二次恢复幂等性；RPG Maker 相邻守卫确认普通方括号仍是正文。没有改写共享缓存。

### 3. Ren'Py 深目录脚本漏预热

影响范围：启动器 Ren'Py 扫描，C/C# 镜像同步。

相同夹具在根目录长 160 字符时能收集原文；根目录长 240 字符、章节文件路径长 279 字符时，两版均漏掉章节对白。读取层已支持长路径，但两处目录枚举仍走传统路径入口。

修复只将该扫描器的文件和子目录枚举接到已有的安全文件 API 边界。`test_renpy_long_scan.py` 的有效反例修复前 4 项失败，候选启动器修复后 19 项通过，包含短/长目录、两层递归、排除自带钩子、精确原文与引擎提示、只读文件快照、C/C# 完整请求一致性，以及 RPG Maker 邻接守卫。已加入完整构建门禁。

这不代表所有扫描器、引擎识别入口、系统配置 API 或第三方游戏运行时已取消路径长度限制。

### 4. 非标准本机地址出现检测假阳性

影响范围：C# API 目录、连通检测及首包等待策略。

`Uri.Host` 会把 `127.1`、整数/十六进制/八进制 IPv4 写法规范化为 `127.0.0.1`，原 C# 检测因而接受这些地址，但 C 启动器和两版翻译服务器按原始主机拒绝，出现检测成功但配置不可用。

现在按原始 authority 判断标准本机主机，与现有服务契约一致。`localhost`、`127.0.0.1`、`[::1]` 的正常本机行为和 120 秒冷启动等待保持不变。修复没有改用户保存的地址。

### 5. API 配置响应校验不一致

影响范围：C 启动器的模型目录及连通响应解析。

C 先前接受未使用字段中的重复键和溢出数字 `1e999`，C# 严格解析拒绝。C 的有界 JSON 索引现在检查所有对象解码后的完整键唯一性，拒绝非有限数字；以排序避免大量元数据触发平方复杂度。转义等价键、长键、NUL/surrogate 键、正常有限数字和未使用的单个 surrogate 元数据均有边界守卫。

### 6. 异常提供商响应可能进入译文缓存

影响范围：四引擎共用的 C/C# 服务器提供商边界。

真实服务反例证实，C 可从截断 JSON、带尾部垃圾的正文或错误层级字段提取 `content` 并当作译文；C# 对坏 UTF-8 字节使用替换字符后继续处理。独立首批反例修复前 14 项中 6 项失败。

修复在提供商响应边界验证完整正文和 UTF-8，并且只接受 `choices[0].message.content` 所属的文本。完整键去重、有限数值、合法未知元数据和实际译文中的 NUL/孤立代理都有相邻守卫。交叉审查还发现 C# 严格模式接受 `\u 041` 一类带空格的非法转义；`Json.ParseStrict` 现在逐字符校验四位十六进制，保留非严格解析入口的既有兼容行为。最终候选程序响应专项 38 项通过，共享核心 143 项通过。

游戏侧请求解析、非阻塞缓存未命中契约和持久缓存格式不随此修复改变。异常只记录类别，不记录提供商正文或认证信息。

## 构建过程中的暂存失败

首次完整构建在 Unity 引用暂存测试的普通指针替换阶段失败，构建输入无漂移。失败夹具保留了旧指针、新的完整快照与未提交的临时指针；测试自身尚未进入显式锁故障注入。原 `Key()` 断言通过对象表格输出错误，截断了真实异常。

测试现直接保留 exit/stdout/stderr；暂存 helper 的替换失败同时记录最底层异常类型、HResult、目标及临时路径。锁故障注入增加了这些字段的断言。保留原子替换、失败传播和旧快照，没有添加重试、删除后移动或覆盖写。

保留夹具直接执行成功，补全诊断后的 PowerShell 5.1 暂存套件 166 项通过。短暂外部共享冲突只是未证实假设，不能据此断言是某个进程占用，也不能称原始失败已彻底消除；后续完整构建结果与该首次失败分别记录。

加入异常字段守卫后的第二次构建遇到测试断言格式问题：PowerShell 5.1 把类型和 HResult 之间折行，最初的断言只匹配单个空格。直接受控锁反例完整记录了 `System.IO.IOException` / `0x80070020`；断言改为接受格式空白，仍要求准确异常类型和八位错误码，并在失败时附原始输出。PowerShell 7 的同套检查 167 项通过。两次失败日志均单独保留，没有覆盖成成功记录。
