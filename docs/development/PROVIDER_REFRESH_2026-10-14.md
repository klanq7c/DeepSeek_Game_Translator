# 提供商切换与模型刷新报错

日期：2026-10-14。基于 0.4.1.0 的本地开发构建。

## 已复现的缺陷与未确认部分

用户报告 OpenAI 等提供商刷新报错，尚未提供具体状态码。
本次不以其他测试通过来推断该账号必定可用。

1. 实际配置控件切换提供商时只换地址和模型，Key 仍属于上一家。
   新增控件守卫在修复前输出 `provider_key_isolated=0` 和
   `provider_key_restored=0`，证明切换语义缺少隔离和返回恢复。
2. HTTP 失败统一显示“厂商返回 HTTP 错误”，用户无法辨别认证、访问、目录或限流问题。
   本地假提供商的 401 原因提示断言在修复前失败。
3. 原生只读、无凭据请求到达 OpenAI `/v1/models` 并收到 HTTP 401，
   只证明该次连接可达及认证缺失，不证明用户填写正确 Key 后一定能获取目录。

依据：[OpenAI 模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)
要求 Bearer 认证；[官方错误码](https://developers.openai.com/api/docs/guides/error-codes)
区分认证、访问限制、额度及限流等原因。

## 修复范围

仅修改 C/C# 启动器 API 配置和模型目录错误提示；不改变翻译请求、缓存或任何引擎 payload。

- 每个提供商预设的 Key 在本次配置窗口中单独保留；首次切换到其他预设时为空，
  切回时恢复对应草稿。同一预设和不改变地址的“自定义”选择保留当前输入。
- 窗口关闭即释放草稿，原生窗口清零 Key 缓冲；不增加磁盘凭据文件，不改变取消语义。
- 内置远程提供商缺少 Key 时，在发请求之前明确提示；本地及自定义无 Key 路径保留。
- 401、403、404、407、429、5xx 分别显示认证、访问、目录、代理认证、请求受限、
  服务暂不可用提示；保留原始 HTTP/传输错误码。不展示可能回显密钥的响应正文，
  不将错误伪装成可用目录。状态码可能有多种原因，提示不替代厂商诊断。
- 独立 C# 测试宿主补齐与正式启动器相同的目标框架和运行时配置，避免测试宿主默认值
  与产品不同。初次独立宿主出现 TLS 错误，不据此断言正式启动器存在相同问题。

## 验证记录与边界

- 模型目录 104 个本地场景通过，C/C# 输出一致；包括新增 HTTP 分类和响应正文不泄漏检查。
- 控件守卫覆盖 Key 隔离、切回恢复、缺少 Key 时不发请求；`build_native.bat` 返回 0，
  启动器一致性 271 场景、四种 DPI 的窗口对照及模型目录等全部内置门禁通过。
- 根目录启动器已重新生成；真实 `config/api.ini` 的 SHA-256 与修复前相同。
- 自动审批拒绝了复制探针后进行外网和手动隐藏窗口检查的组合命令，只返回
  `blocked by policy`，没有具体解释。没有重试该组合操作；之后使用标准构建中的本地门禁。
- 未取得 OpenAI 账号认证成功的实测结果；用户报告的具体 HTTP/传输错误码仍待提供。
- 用户随后询问刷新模型是否需要 API Key。已说明 OpenAI `/v1/models` 需要其 API Key；
  不能把缺少有效厂商凭据时的认证失败当作模型目录版本过期。
- 原始记录只留在本地 `.scratch/provider-refresh/`；不保存真实 Key 或厂商响应正文。
