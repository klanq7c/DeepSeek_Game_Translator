# 0.4.1.1 Unity 构建引用缓存（2026-11-01）

## 范围

本项于 2026-11-01 实施，2026-11-06 完成收尾。基于未提交工作区，版本保持 0.4.1.1。
修改共享构建配方及 Unity Mono/BepInEx 5、6
引用选择；没有修改服务器、四引擎运行时代码、启动器 C/C# 镜像、用户配置或游戏文件。
五个托管组件共用配方指纹，因此本项要求全部真实重建。没有发布、提交或清理历史引用。

## 复现与修复

旧流程从 Mono 输出借用依赖时，每次创建随机目录。交接时有 38 个目录、
2394 个文件、226,186,640 字节；重复选择守卫复现了目录重名失败。没有撞名时，
旧流程也会重复复制相同输入。

新 helper 按 Ordinal 文件名、长度和内容 SHA-256 生成清单及目录键，
位置为 `build/unity-managed-refs/<SHA256>/`。范围为 `UnityEngine*.dll`
和可选 `Unity.TextMeshPro.dll`，必须包含 CoreModule。同一输入校验后复用；
不同字节、文件名或 TMP 成员变化产生不同版本。

发布顺序为独占 `stage.lock` → 读取并验证 current → 枚举源引用 → 新版本复制到
独占 `.pending-*` → 校验目标和重新读取源 → 发布完整版本目录 → 原子更新
`current.txt`。已有版本不修改，旧版本不删除。指针更新失败可能留下完整未选中版本，
但不把半份内容设为 current。失败临时文件保留供诊断。

显式 `UNITY_MANAGED_DIR` 优先，其次为保存的 `UnityManagedRefs`。两者未提供时，
两个 Mono 阶段共用一次缓存选择。非增量编译清空输出后，或第二阶段失败后的下一次
构建，可继续使用已经完整校验的 current。显式错误不自动回退；已存在但损坏的
current/快照、非普通文件、异常快照条目或重解析点会停止构建。

增强测试另确认了两项初版缺陷：

1. `FOR /F` 不保留 PowerShell 子进程退出码；helper 即使先输出合法键再失败，
   原调用者仍会编译并返回成功。现在同时要求唯一的 64 字符大写十六进制键及
   CMD 在子进程成功后才输出的成功标记；多余输出、空输出或非法键均失败。
2. Windows PowerShell 5.1 将 `File.Replace` 的普通 `$null` 参数绑定为空路径，
   第二个版本无法更新 current。改用项目既有指纹发布器采用的
   `[NullString]::Value`，并在替换失败时记录目标、临时路径和原错误。

测试入口也按真实 `build_native.bat` 的 `CALL` 方式调用完整托管批处理，
避免以直接调用的 CMD 状态冒充实际调用者状态。编译边界使用拥有的真正 EXE，
不是会转移批处理控制流的 `.cmd` 替身。PowerShell helper 保持 UTF-8 BOM；
BAT 保持 ASCII。

## 回归守卫

- `tests/build_artifacts/test_unity_reference_staging.ps1`：真实 helper 与真实完整批处理，
  只替换编译器及指纹记录外部边界。覆盖引用字节、目录/文件/mtime 无增长、
  两阶段共用、清理后的引用存在、第二阶段失败与下次重建、失败不写指纹、
  显式/保存引用优先级、helper 退出/输出协议、内容版本变化、损坏内容、
  文件锁与恢复、复制/验证/源变化/目录发布/指针替换故障、重解析点、中文/空格路径。
  故障注入仅改隔离夹具中的真实源码副本，生产 helper 没有测试开关。
- `tests/build_artifacts/test_managed_stamp_write.ps1`：保留原映射读取/锁冲突/原子写入守卫，
  新增源链接真实 `Get-ManagedPayloadDefinitions`，只改 helper 字节、保持 mtime，
  要求五份旧配方指纹恰好全部失效。
- `scripts/verify_build_artifacts.ps1`：helper 持续参与五个托管配方。
  源码打包沿用 `scripts` 白名单，构建引用缓存位于排除的 `build` 下。
- 完整构建保留共享核心、Unity runtime contract、C/C# 启动器 parity、
  持久化/缓冲/API/预热等相邻门禁，保护其他引擎与共享契约。

第 2406 行对应断言，被既有密码赋值正则识别为可能的凭据。二者均为本项之前已有的
UI 诊断，不包含用户密码。没有为本项改写探针或放宽发布扫描；源码目录已包含新 helper，
但不能据此宣称当时整份源码包通过发布审计。随后在 2026-11-06 的独立修复中处理了
该误报及单字符凭据漏检；当前结果与边界见 [源码扫描修复记录](RELEASE_CONTENT_SCAN_2026-11-06.md)。

原始日志、每轮目录/哈希快照、退出码及最终 `verification.json` 保存在本地
`.scratch/unity-reference-cache-2026-10-31/`；目录名是本项起始证据目录，不表示所有检查的执行日期。

## 边界

复用减少相同输入的重复复制和目录增长；未测量构建速度、内存或游戏 FPS，
不据此宣称性能百分比。历史随机目录和不同内容版本仍保留，不是全目录总量限制。
发布锁只保护引用发布，不承诺多个完整构建可同时写同一输出。

Godot 3.6 的旧运行时阻塞仍未重测或修复；本轮配置的真实脚本引擎为
Ren'Py 7.8.7、8.1.1 和 Godot 4.3。任何构建、夹具或静态检查结果均不是完整游戏游玩证明。
