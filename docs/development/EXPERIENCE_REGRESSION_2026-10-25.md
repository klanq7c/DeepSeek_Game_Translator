# 经验优化后的边界复查（2026-10-25）

本轮仅复查上一轮经验优化的影响，不重写用户游戏、配置或翻译记忆。
影响范围：Ren'Py hook、Unity IL2CPP 字体显示层，以及 Godot 启动器预检与 C# 镜像。

## Ren'Py：合法旧式键名被误拒绝

上一轮新增的映射字段校验使用 `[^)]+` 识别键名，会误拒绝 `%()s`、
`%(player(name))s`、`%(score(round(1)))03d` 等 Python 允许的键。
正式恢复入口在三个源文上退回英文并记录格式异常，新增用例先复现四个失败断言。

现在按 Python 的平衡括号规则读取完整映射键，再检查格式后缀；保留原字段的
类型、宽度和位置规则。新增、缺失及不闭合字段仍拒绝，不放宽已有防注入检查。
普通百分号、转义字面量及其他引擎的占位符逻辑保持原路径。

## Unity：可见文字不能被当成不透明属性

上一轮字体入口将所有尖括号片段遮住，但 TMP 的 `<noparse>` 内文字应直接显示，
未知标签及无效的数字/颜色样式也可能按字面显示，UGUI 支持的标签又少于 TMP。
原实现复现五个失败断言，包括缺失字体触发和字形预热漏掉可见中文。

现在只有已识别的 TMP 资源或标识属性可被遮住，并在字体扫描中保留 noparse 状态。
普通标签中的非 CJK 字符不进入请求字形集合；未知样式中的 CJK 仍会检查覆盖。
UGUI 保守按字面检查，以免拿 TMP 语法遮掉它实际显示的文字。
真实 link 标识仍保持不透明；语言分类、公共缓存与共享标签解析器没有改动。

依据：[TMP noparse](https://docs.unity.cn/Packages/com.unity.textmeshpro%404.0/manual/RichTextNoParse.html)、
[Legacy Unity Rich Text](https://docs.unity3d.com/2021.3/Documentation/Manual/StyledText.html)。
这只处理字体需求，不能替游戏修复无效标签或缺失的原生字体资源。

## Godot：新增 ACK 超出旧读取窗口

在真实两版启动流程中加入启动日志夹具：前缀长度 16350 字节，ready 完整位于
原 16 KiB 窗口内，而 ACK 跨过上限。两版均错误超时并退到 `--script`，
新增分支断言明确失败；旧的一行 ready 规则在相同前缀下会通过。

现在独立读取句柄持续前进；解析器只保留 64 字节行状态和 ready 状态，
不累计日志正文。每轮至多读 512 KiB，保留既有退出状态、专用停止码和五秒期限。
凭据可以跨字节块、CRLF 可以拆开；长行和含 NUL 的行不能伪装成完整凭据。
原崩溃断言及其他预检分支没有削弱，子进程协议不改，既有成功缓存仍有效。

## 验证

- Ren'Py 正式恢复入口 10 项通过，包含在 Python 实际格式化前后核对嵌套及空键。
- Unity 正式方法源链接守卫 216 项通过；原生 FontEngine 仍由夹具模拟，不等于 Unity 游戏全流程测试。
- Godot 正式解析器在每版 36 个分块场景通过；原进程收尾的 13 个确定性场景继续通过。
- 初次直接 parity 的 C 二进制仍嵌入旧 Ren'Py hook，而 C# 按源码重编译，产生 12 个部署快照差异；单独记录构建状态差异。新增 Godot 日志分支的实际超时另计一个失败。最终完整构建统一重编译两版后，上述差异和失败全部消失；原有断言均保留。
- Payload 128 项通过，配置的真实 Ren'Py 7.8.7 / 8.1.1 执行源码与原编译脚本两阶段，Godot 3.6 / 4.3 继续执行生成器及运行时检查，RPG Maker 相邻检查通过。
- 最终 `build_native.bat` 完成、退出码 0；Unity 216 项、launcher parity 283 项均无失败，包含跨日志块的实际启动分支。缓存、缓冲区、API 边界、模型目录、混排及本地优先等其余构建门禁通过。没有运行 `-ServerSmoke`，未使用真实远程提供方验证。
- 原始日志位于本机 `.scratch/experience-regression-2026-10-25/`；最终构建为 `build.log`，脚本检查为 `payload.log`，新增用例修复前后的日志保留作复现依据。
