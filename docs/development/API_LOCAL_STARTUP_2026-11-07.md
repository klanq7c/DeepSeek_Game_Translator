# 连通检测：本地模型首次加载超时（2026-11-07）

范围：启动器检测请求及其 C/C# 镜像；不修改服务器翻译契约、模型部署或游戏适配器。版本仍为未发布的 0.4.1.1。

## 复现与原因

用户配置本机 Ollama 的 `index-translate:2b-q5km`，模型目录成功返回，但检测显示 `HTTP 0 / 错误 12002`。

在同一运行中的 Ollama 上，先以 `/api/ps` 确认没有已加载模型。原生生产检测请求约 16.031 秒后报告相同超时，模型仍未驻留。只增加客户端等待的同一请求约 33.031 秒后返回 HTTP 200 和 `OK`；模型驻留后，原来的检测约 0.125 秒成功。由此排除了地址、空 Key 和短提示词不兼容，确认检测的 15 秒响应等待不足以覆盖本地首次加载。33 秒是整个请求时间，不单独当作模型加载耗时。

Ollama 的兼容聊天接口与模型列表是不同请求；列表可用不能证明模型已经完成推理准备。协议依据：[Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility)。

## 修复

- HTTP/HTTPS 的规范回环主机 `localhost`、`127.0.0.1` 和 `::1` 使用 120 秒响应等待；远程地址保留 15 秒。
- 窗口与请求共用同一等待策略，增加本地首次加载提示；其他界面布局不变。
- 加载属于外部推理服务控制范围。修复不自动重试、切换模型或把目录成功视为聊天成功。错误仍返回阶段和状态码。
- 收到响应头后仍使用 15 秒正文读取超时，同时保留响应体大小和累计读取限制，避免冷启动预算放大异常响应体的等待。
- 这些是传输阶段的等待限制，不将其表述为整个操作严格等于 120 秒的总截止时间。

## 验证记录

本地原始记录位于 `.scratch/api-local-timeout-2026-11-07/`，包含真实请求对照、旧版失败和新版成功的 18 秒延迟夹具。最终构建与实测结果见该目录 `verification.json`。完整构建退出 0，244 个源码与测试输入无漂移；连通检测 56 组、启动器 parity 284 项和四档 DPI 位图比较均通过。

补充 35 秒响应延迟夹具分别在 35.062 / 35.453 秒成功，覆盖实际曾出现的 33 秒等待。真实模型自然卸载后，再以生产检测函数测试：C 版 2.250 秒成功，随后 C# 版 0.140 秒成功。第二次未驻留状态的加载耗时与首次启动准备不同，不将其当作对首次 33 秒等待的否定。

此次遗漏来自首次实现只覆盖快速成功及超时失败，没有覆盖本地提供商合理的慢启动成功分支。新增的 18 秒延迟成功测试、10 个本机/远程地址策略测试、正文挂起测试和真实 120 秒超时测试共同防止回归；不会以放宽成功响应校验来消除失败。

未重启或更改用户 Ollama 服务，未卸载/切换模型，未更改真实 API 配置或翻译记忆。真实测试仅针对用户指定的本机模型，不代表所有云端账号、其他模型或翻译质量。
